# luci-app-switch2-block
**简体中文** | [English](./README_EN.md)

本插件让 Switch 2 / Switch 1 在本地通过任天堂连接测试，同时禁止已登记网卡通过本路由器访问互联网。**主机通过连接测试，并不证明外网已经隔离。**

## 安装已签名的 APK（OpenWrt 25.12 及以上）

下载新版 `.apk`，并从本仓库获取[项目公钥](./luci-app-switch2-block-apk.pem)。信任前先核对公钥文件校验值：

```sh
echo 'cc1834e4ae149c861f6ae203d70304a864ba1cf2b1bbecb338d18fcc8f473296  luci-app-switch2-block-apk.pem' | sha256sum -c -
```

将公钥和 APK 上传到路由器，以 root 身份将公钥移入 `/etc/apk/keys/`，再通过 LuCI 或 `apk add /tmp/<package>.apk` 安装。添加此公钥后，路由器将信任由本项目签名的软件包；旧的未签名包仍无法通过验证。

## 启用前

**不要用上游 APK/IPK 覆盖本分支，即使上游版本号更高。两者包名相同，但上游没有本分支的启动防护和完整隔离检查。更换软件包前请先断开主机。**

**此工作流不发布 IPK 升级包。** 测试发现，从旧版本分支 IPK 升级时，旧包的卸载脚本会在新包运行前删除生效的防护规则，opkg 也会覆盖网卡登记配置。请勿用旧版 IPK 进行原地升级；opkg 安装成功并不表示隔离已生效。

1. 安装、升级、登记网卡期间请让主机保持离线。备份 `/etc/config/` 下的 `network`、`dhcp`、`uhttpd`、`firewall` 和 `switch2-block`。从旧版升级时，旧包的卸载脚本可能移除旧防火墙规则。
2. **本 OpenWrt 设备必须是唯一出口。** 使用独立有线网段或隔离的 SSID，不允许主机经其他客户端、AP、网关或硬件交换路径上网。辅助服务使用 `br-lan` 上的 `lan` 网络，以及同一 `/24` 内未占用的 IPv4 地址。在共享局域网里仅修改 DNS、使用旁路由并不能保证隔离。
3. 关闭软硬件流量卸载及厂商网络加速，修改后先断网重启。不支持绕过 Linux 过滤、在防护服务前启动网络或清空第三方 nftables 表的固件。代理插件不得截获主机流量，本地 DHCP、辅助 DNS 和 HTTP 端口不得转发到外网。
4. 在 **网络 → Switch 2 Blocker** 中分别登记主机无线网卡和每个有线底座/转接器的真实 MAC。所有登记项都必须开启阻断，删除无效的旧条目。本插件不会自动识别任天堂设备；新底座、其他 Wi-Fi 和手机热点不在保护范围内。
   本地辅助服务最多支持八个不重复的连接测试域名。若不需要增加本地测试响应，请保留默认值。增加域名不会授予外网访问权限。
5. 开启插件，点击**保存并应用**，主机使用自动 IPv4/DNS。保持真实 WAN 断开，先用登记过的测试客户端和隔离的 WAN 测试服务器验证：本地 DNS 和 HTTP 正常；同一端口或 SSID 上的受控客户端无法通过 IPv4 或 IPv6 到达服务器；未登记客户端可以到达。重载防火墙和重启路由器后重复验证，再决定是否接入真实 WAN。

## 防护机制

不论主防火墙采用 fw3 还是 fw4，都需要内核及 nftables 支持 `inet`、`bridge` 和 socket 匹配。插件不根据命令是否存在猜测防火墙类型，不再向 `/etc/firewall.user` 写入规则。缺少内核模块的固件不受支持。

受控网卡仅可使用本地 IPv4 DHCP、辅助地址的 DNS（TCP/UDP 53）和 HTTP（TCP 80），以及本地 ARP 地址解析。经本机路由的 IPv4/IPv6 和经软件网桥转发的流量均被阻断。辅助 DNS 不使用上游服务器。防护规则不匹配其他网卡。

独立的 nftables 规则通过单个事务替换，不依赖主防火墙重启。停止、重启辅助服务或正常关机不会解除防护。**主动关闭插件或卸载会解除防护**，操作前请先断开主机。

## 自检与恢复

自检检查路由器上的辅助服务和运行中的规则，不能证明主机实际出站流量、未登记的底座或硬件交换路径已被阻断。命令行检查：

```sh
/usr/libexec/switch2-block/policy.sh check
```

启用失败时，不要连接新登记的网卡。被拒绝的配置不会生效；不会为了尝试新规则而先撤销现有防护。请查看 `logread -e switch2-block` 并修复配置。

**启动失败会影响整台路由器：** 开启防护后，如果无法在启动早期恢复并应用规则，系统将暂停正常网络启动，LuCI 和 SSH 可能无法访问。断开主机，通过本地控制台或 OpenWrt 的 failsafe 模式（必要时执行 `mount_root`）修复配置。若明确决定关闭防护：

```sh
uci set switch2-block.global.enabled='0'
uci commit switch2-block
reboot
```
